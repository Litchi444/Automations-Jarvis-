## Why this matters

The project generates four n8n workflow JSON files from `src/build_workflows.py`.
Code-node sources (`src/**/*.js`) and n8n expressions inside the generator read
other nodes' output by name, e.g. `$('Prepare agent input').first().json`. n8n
only resolves these names at **runtime**, so renaming a node in the generator
(or typo-ing a name in a `.js` file) produces a workflow that imports fine and
then crashes on the first real Telegram message. The unit tests do not catch it
either: `tests/code_nodes.test.js` mocks nodes by name independently of the
generator. After this plan, `python3 src/build_workflows.py` exits non-zero
naming the bad reference, before anything is written.

## Current state

- `src/build_workflows.py` — the generator. Class `WF` collects nodes and

  `src/build_workflows.py:61-69` (current validation, edges only):
  ```python
  def write(self, filename):
      names = {n["name"] for n in self.nodes}
      assert len(names) == len(self.nodes), "duplicate node names"
      for src, kinds in self.connections.items():
          assert src in names, f"{self.name}: unknown source {src}"
          for outs in kinds.values():
              for edges in outs:
                  for e in edges:
                      assert e["node"] in names, f"{self.name}: unknown target {e['node']}"
  ```
- Node references live in two places, both inside `n["parameters"]` once built:
  1. `jsCode` strings (Code nodes load `src/*.js` via `code(rel)`), e.g.
     `src/assistant/parse_agent_output.js:5`: `const ctx = $('Prepare agent input').first().json;`
  2. n8n expression strings in the generator, e.g.
     `src/build_workflows.py:119`: `cfg = "$('Config').first().json"` and
     `src/build_workflows.py:276`: `route = "$('Route update').first().json"`.
- Reference syntax in use today is always single-quoted: `$('Name')`. There
  are 10 such references across `src/**/*.js`. Names contain spaces and `+`
  (e.g. `Parse + validate`), never a single quote.
- Each workflow is self-contained: a `$('Config')` in the Speak workflow refers
  to Speak's own `Config` node, not the briefing's. Validate per workflow.
- Repo style for generator checks: plain `assert` with an f-string message
  prefixed by `self.name` (see the excerpt above). Match it.

## Steps

### Step 1: Add a reference scanner

Add near the other module-level helpers (after `read()`, around line 36):

```python
NODE_REF = re.compile(r"\$\('([^']+)'\)")


def node_refs(value):
    """Every $('Name') used anywhere in a node's parameters (code and expressions)."""
    if isinstance(value, dict):
        return {r for v in value.values() for r in node_refs(v)}
    if isinstance(value, list):
        return {r for v in value for r in node_refs(v)}
    return set(NODE_REF.findall(value)) if isinstance(value, str) else set()
```

`re` is already imported (line 11).

**Verify**: `python3 -c "import sys; sys.path.insert(0,'src'); import build_workflows as b; print(sorted(b.node_refs({'a':\"\$('X').first()\",'b':[\"\$('Y + z')\"]})))"`
